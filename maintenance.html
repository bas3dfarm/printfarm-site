Обслуговування

Усе, що знадобиться після встановлення: де лежать дані, як читати журнал, оновлювати, робити бекап і що робити, коли щось пішло не так. Команди виконуються в терміналі комп'ютера ферми.

Де що лежить

ШляхЩо
/opt/printfarm/програма — не редагувати, замінюється при оновленні
/etc/printfarm/config.envналаштування (порт тощо); оновлення його не перетирає
/var/lib/printfarm/дані: база printfarm.db, файли задач uploads/, бекапи backups/
журнал systemdжурнал подій сервера: journalctl -u printfarm

Каталог даних доступний лише службі: у базі — Access Code принтерів і хеші паролів.

Служба

systemctl status printfarm          # працює? скільки пам'яті, з якого часу
sudo systemctl restart printfarm    # перезапуск (після зміни config.env)

Принтери друкують самі. Перезапуск, оновлення чи перезавантаження комп'ютера ферми друк не зупиняють: після старту сервер підхоплює поточні друки й продовжує їх облік.

Журнал подій

Журнал — перше місце, куди дивитись, коли принтер «офлайн», задача не відправилась чи камера не показує. Сервер пише туди кожну зміну стану принтера, відправку друку і помилки.

Основні команди

journalctl -u printfarm -f                    # наживо (вийти — Ctrl+C)
journalctl -u printfarm -n 200 --no-pager     # останні 200 рядків
journalctl -u printfarm -b                    # з останнього завантаження комп'ютера
journalctl -u printfarm --since "1 hour ago"  # за останню годину
journalctl -u printfarm --since "2026-11-20 08:00" --until "2026-11-20 12:00"

Знайти потрібне

journalctl -u printfarm --since today | grep "X1C-08"          # усе про один принтер (за назвою)
journalctl -u printfarm --since today | grep -E "❌|⚠️"          # лише помилки й попередження
journalctl -u printfarm --since today | grep "не відправлено"   # чому задача не пішла на принтер

Що часто трапляється в журналі

ЗаписЩо це і що робити
Not authorizedBambu: невірний Access Code, або за цією адресою тепер інший принтер — див. «Принтери змінили IP».
ECONNREFUSED, EHOSTUNREACHза адресою немає принтера: вимкнений або змінив IP.
ENETUNREACH одразу після перезавантаженнясервер стартував раніше, ніж мережа. Через кілька секунд підключиться сам — не помилка.
0x05024007Bambu відхилив друк: увімкніть на принтері LAN Only + Developer Mode.
spawn ffmpeg ENOENT, ffmpeg не знайденодля камер X1 / H2 потрібен ffmpeg: sudo apt install ffmpeg і перезапуск.

Надіслати журнал для допомоги

journalctl -u printfarm --since "2 hours ago" --no-pager > ~/printfarm-log.txt

Файл printfarm-log.txt з'явиться в домашній теці. Паролів і Access Code у журналі немає, але там є назви принтерів, файлів і IP-адреси вашої мережі.

Оновлення

Новий файл пакета ставиться тією самою командою поверх старого:

sudo apt install /tmp/printfarm_<нова-версія>_amd64.deb
  • Перед оновленням пакет сам робить бекап бази (у виводі: ✅ Бекап створено: …). Не вдалося — оновлення скасовується, стара версія працює далі.
  • Ферма недоступна ~5 секунд. Дані, принтери, налаштування й вхід лишаються — заново входити не треба.
  • Коли ставити: у момент, коли мало активних друків. Друки не зупиняться, але так простіше перевірити, що все гаразд.
  • Після оновлення перевірте: 
    dpkg -l printfarm | tail -1                  # яка версія стоїть
systemctl status printfarm --no-pager        # служба працює
journalctl -u printfarm -n 50 --no-pager     # немає ❌ після старту
  • Відкат: база оновлюється лише вперед, тож повернення до старої версії — це стара версія пакета плюс база з бекапу, зробленого перед оновленням. Якщо знадобиться — напишіть нам, допоможемо.

Бекапи

  • Автоматично: щодня о 00:15 у /var/lib/printfarm/backups/, зберігаються останні 14; плюс перед кожним оновленням.
  • Вручну (перед ризиковою дією): 
    sudo runuser -u printfarm -- sh -c 'set -a; . /etc/printfarm/config.env; set +a; exec /opt/printfarm/node/bin/node /opt/printfarm/backup-db.js'
sudo ls -lt /var/lib/printfarm/backups | head -3
  • Копія поза комп'ютером. Бекапи лежать на тому самому диску. Якщо диск помре — пропадуть разом з базою. Періодично копіюйте теку backups на флешку чи інший комп'ютер: 
    sudo cp -r /var/lib/printfarm/backups ~/printfarm-backups

Забули пароль

sudo printfarm-reset-password            # якщо адміністратор один (кілька — підкаже логіни)
sudo printfarm-reset-password <логін>    # конкретний користувач

Команда друкує тимчасовий пароль; вхід цього користувача в усіх браузерах скинуто. Увійдіть з ним і задайте свій: меню користувача (вгорі праворуч) → «Змінити пароль».

Принтери змінили IP

Ознака: після перезавантаження роутера чи відключення світла більшість Bambu «офлайн», у журналі Not authorized або ECONNREFUSED. Роутер роздав нові адреси, а ферма стукає на старі.

sudo printfarm-find-printers            # лише показати: хто де і що змінити
sudo printfarm-find-printers --apply    # змінити IP (спитає логін і пароль адміністратора ферми)
  • Принтер впізнається за серійним номером — команд принтерам не шле.
  • «Нова адреса … ще за іншим принтером» — той принтер вимкнений або не знайдений: змініть його IP в інтерфейсі і запустіть команду ще раз.
  • «Двічі в базі» — той самий принтер доданий двома записами: видаліть зайвий в інтерфейсі.
  • Принтери в іншій підмережі: sudo printfarm-find-printers --subnet 192.168.2 (перші три числа їхньої адреси).
  • Щоб не повторювалось — закріпіть адреси в роутері (DHCP reservation).

Змінити порт

sudo nano /etc/printfarm/config.env   # рядок PORT=3100 (від 1024 до 65535)
sudo systemctl restart printfarm

Ярлик у меню підхопить новий порт сам. Якщо увімкнений ufw — відкрийте порт: sudo ufw allow 3100/tcp.

Аварійні перемикачі

Деякі нові функції можна вимкнути без повернення до старої версії: дописати рядок у /etc/printfarm/config.env і перезапустити службу.

РядокКоли знадобиться
PRINTFARM_3MF_TITLE=offякась модель Bambu після оновлення відмовляється друкувати файл з ферми. Повтори з екрана X1C тоді знову підуть у «поза задачами».
PRINTFARM_BAMBU_PROBLEM=off наступна версіяпричина паузи Bambu показується неправильно чи заважає. Пауза буде без коду й тексту, як раніше.
PRINTFARM_BAMBU_ACTIONS=off наступна версіякнопки в блоці «Причина паузи» поводяться не так. Повернеться проста кнопка «Відновити друк».

Типові проблеми

Сторінка не відкривається з іншого комп'ютера

Увімкнений файрвол без правила для порту (sudo ufw status; відкрити — sudo ufw allow 3000/tcp) або змінено порт у config.env.

Після встановлення не заходить по SSH / віддаленому робочому столу

Якщо ufw закриває вхідні з'єднання, пакет відкриває лише свої порти. Дозвольте SSH з локальної мережі (підмережа — ваша):

sudo ufw allow from 192.168.1.0/24 to any port 22 proto tcp comment 'SSH (LAN)'

Так само порт 3389 для RDP. Зробіть це до того, як від'єднаєте від комп'ютера монітор.

Safari на Mac відкриває ферму, а Chrome — ні

macOS не дав Chrome доступу до локальної мережі: Системні параметри → Конфіденційність і безпека → Локальна мережа → увімкнути Google Chrome і перезапустити його.

Служба не стартує

journalctl -u printfarm -b. Найчастіше порт зайнятий іншою програмою (sudo ss -ltnp | grep :3000) — змініть PORT у config.env.

Принтер не підключається

  • Bambu: перевірте Access Code і серійник; для друку з ферми — LAN Only + Developer Mode.
  • Klipper: IP; API Key — лише якщо увімкнена авторизація Moonraker.
  • Prusa: IP і API Key.

Камера не показує

На старті в журналі має бути рядок 🎞 ffmpeg: …. Немає — sudo apt install ffmpeg і перезапуск. P1 / A1 і Klipper-принтери ffmpeg не потребують.

Нічні друки потрапляють у вчорашній день

Неправильна часова зона комп'ютера — див. «Мережа й час».

Видалення

sudo apt remove printfarm   # прибрати програму; дані, налаштування й історія лишаються
sudo apt purge printfarm    # прибрати ВСЕ: базу, файли задач, бекапи, налаштування

Після remove повторне встановлення продовжить з тими самими принтерами й історією. purge — незворотно: спершу скопіюйте бекапи (див. «Бекапи»).
